# 7〜9. 法廷記録と通知・再訪と捜査の終わり・点検

探偵編を先へ進め、法廷編へつなぐまで。最後に、探偵編全体の点検をまとめる。

## 7. 法廷記録と通知

**決めること:** 証拠品の名前と説明文（法廷で何を示すか）・知らせの形（作品の中で 1 つにそろえる）・人物ファイルを加える所。

- **制約:** 証拠品の名前は 10 字、説明文は 1 行 12 字 × 3 行まで（4 行目は出ない）。人物ファイルは「名前（年齢）」で 10 字
  （[文字数の決まり](../text-length.md)）。`give` で証拠品の詳細が画面の上に出る。
- **証拠品の入手（傾向）:** 気づきの音 + フラッシュ（揺らさない）→ 主人公の心の声で要の語を赤 → `give` → 名前なしの青字で
  「証拠品《○○》を法廷記録にファイルした。」（探偵パートで 10 話）。探偵パートの `give` 247 のうち 196 で、3 ステップ以内に知らせが続く
  （[決まり文句の集計](../numbers/phrases.md)）。「《○○》のデータを」とする形が多く、「《○○》を法廷記録に挟んだ。」（10 話）もある。
- **証拠品の更新（傾向）:** 中身が変わるときは、古いものを `take` して新しい版を `give` し、
  「証拠品《○○》のデータを書きなおした。」（7 話）と知らせる。
- **人物ファイル（傾向）:** 知らせの文を出さない（`giveProfile` 241・`takeProfile` 122）。初めて会った人物を `giveProfile` で加え、
  更新は `takeProfile` + `giveProfile` で版を差し替える。
- **推奨:** 知らせの形は作品の中で 1 つにそろえる。新しい証拠品を手に入れた直後に、助手の一言（「それ、使えそうですね」の類）を足すと気づきやすい。

**実例:** 証拠品を手に入れたときと、書きなおしたときの知らせ（元の YAML から、フラグの行を省いた）。

> 出典: 蘇る逆転 第2話（探偵1 の《解剖記録》と、法廷1 での書きなおし）

```yaml
- give: e24
- say: null
  text: "[speed 5]証拠品《解剖記録》のデータを\n法廷記録にファイルした。"
  color: blue
- take: e24
- give: e39
- say: null
  text: "証拠品《解剖記録》のデータを\n書きなおした。"
  color: blue
```

自作の例（詰め所で《手袋》を手に入れる）:

```yaml
tsumesho:
  name: 夜警の詰め所
  enter:
    - if: not visited(tsumesho)
      then:
        - card: "同日 某時刻\n夜警の詰め所"
        - sayo: "ここが、[wait 8]\n倉田さんの詰め所ですね。"
  examine:
    - id: gloves
      name: 棚の手袋
      area: [40, 64, 48, 40]
      then:
        - if: not has(gloves)
          then:
            - naruse: "（手袋だ。[wait 10]片方だけ、\n　黒く汚れている‥‥）"
            - se: discover
            - flash: true
            - naruse: "（この汚れ、[wait 10]\n　倉庫の床の[color red]油[color blue]と同じだ）"
            - give: gloves
            - say: null
              text: "[speed 5]証拠品《手袋》を\n法廷記録にファイルした。"
              color: blue
            - sayo: "それ、[wait 8]\n使えそうですね！"
          else:
            - naruse: "（手袋のあった棚だ）"
  examineDefault:
    - naruse: 手がかりになるものはない。
  move:
    - souko
    - menkai
    - to: court_gate
      when: has(gloves)
```

**点検:** 同じ証拠品の知らせが 2 回出る道が無いか（`if: not has(...)`）。説明文だけで、法廷で何を示すかが分かるか。

## 8. 再訪と捜査の終わり

**決めること:** 状況が変わった後に、同じ場所・人物で何が変わるか。探偵編を出る条件と、出る前に止める言葉。

### 再訪

- **推奨:** 証拠品を手に入れた所・話した話題は、2 回目に短い反応にする（[調べる・話す・つきつける](flow.md#4-調べる) の `else`）。
  状況が変わったら（ロックを外した・新しい証拠品を持っている）、`enter` や話題を `when` で差し替えて、新しい一言を出す。
- **推奨:** 再訪で変わるものは、プレイヤーが次に何をすればよいかの手がかりにする。何も変わらない再訪は 1 ページで済ませる。

### 捜査の終わり

- **条件:** 次の法廷に要る証拠品がそろい、サイコ・ロックを外したら、法廷へ移る。
- **早すぎるとき（傾向）:** 条件がそろわないうちに法廷へ向かおうとしたら、主人公の心の声で止める。
  定番は「（今はまだ、証拠が足りないのかもしれない）」（6 話）。
- **並び（推奨）:** 主人公と助手の短い会話で今日を振り返る（2〜4 ページ）→ BGM を止める（60 フレームのフェード）→ フェードアウト。
- **日が変わるとき:** フェードアウト → 次の日のカード（「○月○日　午前○時○分」）→ フェードイン。前の日の法廷から戻るとき
  （[反論から判決まで](../trial/climax.md#日をまたぐ)）も、この形で始める。

```yaml
day2:
  - card: "10月4日 午前9時\n港の第3倉庫"
  - fade: in
  - bgm: investigation
    frames: 30
  - sayo: "今日で、[wait 8]\n決着をつけましょう！"
  - naruse: "（ああ。[wait 10]\n　もう一度、倉庫からだ）"
  - investigate: souko
```

### 法廷へのつなぎ

- 法廷へ移る場所に来たら、主人公の心の声で決意を言い、フェードアウトして法廷編の最初のシーンへ `goto`。
- 法廷編は、控え室のカード（「地方裁判所　被告人第○控え室」）か法廷のカードで始める（[開廷から証言まで](../trial/opening.md#控え室1-日目の前置き)）。
- **推奨:** 探偵編の終わりに助手が次の法廷の見どころ（相手の検事・証人）を言っておくと、法廷編の頭が短くて済む。
- **制約:** ロックを外さないまま法廷へ進める道があると、クリアまでにロックが残るので整合性チェックがエラーにする。

```yaml
court_gate:
  name: 地方裁判所
  enter:
    - if: not unlocked
      then:
        - naruse: "（今はまだ、[wait 10]証拠が\n　足りないのかもしれない）"
        - sayo: "倉田さん、[wait 8]まだ何か\n隠してる気がします。"
        - investigate: tsumesho
    - sayo: "明日の証人は、[wait 8]\nきっと倉田さんですね。"
    - naruse: "（証拠はそろった。[wait 12]\n　あとは、法廷で崩すだけだ）"
    - bgm: null
      frames: 60
    - fade: out
      frames: 48
    - goto: court_lobby
```

## 9. 会話・演出・完成例の点検

探偵編を書き終えたら、次の順に確かめる。この章の例（倉庫・面会室・詰め所・サイコ・ロック）は、裁判パートの例とつないだ章で
すべて通してある。

| 点検 | 方法・見るもの |
|---|---|
| 次の法廷の対応表の「事前に分かること」が、すべて手に入るか | [探偵パートの設計](design.md#1-この捜査で何を知るか) の表と、`bun run check 章.yaml`（詰み・手に入らない証拠品） |
| 総当たりにならないか | 各話題・調べる所の最後で、次の行き先かくらべるものが分かるか |
| 再訪で同じ発見をくり返さないか | 証拠品の所の `if: not has(...)`、話題の `when` |
| 真相を法廷の前に言い切っていないか | 動揺の反応・ロックの本音が、崩す前の嘘を残しているか |
| 掛け合い | 調べる所の反応が、主人公と助手の性格を見せているか（口ぐせだけになっていないか） |
| 演出 | 気づきの音 + フラッシュは発見の所だけ。揺れは動揺の所だけ |
| 字数 | `bun run check --check-fit 章.yaml`（台詞の 2 行・話題 13 字・移動先 15 字・名前 10 字・説明 12 字 × 3 行） |
| フォント | `bun run check --check-font 章.yaml` |
| 決まり文句と知らせの形 | [決まり文句（探偵パート）](phrases.md) の形で、作品の中でそろっているか |

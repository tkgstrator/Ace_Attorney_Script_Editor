# シナリオの書き方（遊び）

[シナリオの書き方](scenario.md) の続き。元のゲームの遊びのうち、書き方の長いものをここにまとめる。

## サイコ・ロック（逆転裁判2・3）

人物の心の錠（サイコ・ロック）を、証拠品をつきつけて外す遊び。章全体に、挑むのに使う証拠品（勾玉）と
解除したときに回復するライフを書き、ロックそのものはステップ `psycheLock` で決める。

> 出典: 逆転裁判2 第2話（探偵パート1 の、はじめてのサイコ・ロック。ID は読みやすく書き直した）

```yaml
psycheLock: { keys: [magatama], heal: 40 }   # 章全体（トップレベル）
life: 80                                      # ライフの最大（ゲージで出す。10 を超えると棒のゲージ）

# ステップ
- psycheLock: lock0          # ロックの ID（書いた欄だけ変わる。書くとロックが有効になる）
  locks: 1                   # 錠の数
  person: ini                # ロックのかかった人物
  place: waiting_room        # その人物がいる場所
  start: lock_start          # 勾玉をつきつけたときのシーン
  quit: lock_quit            # 「やめる」を選んだときのシーン
  gaugeOut: lock_out         # 挑戦中にライフが尽きたときのシーン（ライフは 1 に戻る。ゲームオーバーにならない）
- lifeRisk: 8                # 見当違いのときに減る量を予告する（ゲージの点滅）
- demand: ...
  by: phoenix
  giveUp: true               # 「やめる」を出す（選ぶと quit のシーンへ。ロックは有効なまま）
  present:
    e40:                     # 証拠品 ID
      - breakLock: true      # 錠を 1 つ壊す。最後の錠なら解除（回復し、ロックを無効にする）
  wrong:
    - phoenix: これが、その証拠です!
    - penalty: risk          # 予告した量だけ減らす
```

- 場所 `place` で、そこにいる人物が `person` の有効なロックがあれば、`keys` の証拠品をつきつけると挑む
  （錠は全部そろった状態から始まり、`start` のシーンへ）。無ければ、その場所のふつうの `present` の反応。
- 錠が 5 つより多いときは、残りを 5 にしてから壊す（元のゲームと同じ。逆転裁判3 の第 5 話の春美は錠 6 つで、5 回壊すと解除）。
- `breakLock: hold` は錠を壊しても解除しない（台本で複数の錠を続けて壊す場面）。`unlock: true` はその場で解除する。
- `quitLock: true` は挑戦をやめて `quit` のシーンへ（demand の `giveUp` と同じ。選択肢の「やめる」に使う。挑戦中でなければ何もしない）。
- 話題に `locked: 条件` を書くと、条件が真の間、その話題にロックの印を出す（既読の印の代わり）。
- 錠の表示は `ui: { locks: 3 }`（出す）・`ui: { locks: false }`（隠す）・`ui: { locks: true }`（出し直す）。
  挑むとき・壊すとき・解除するときは自動で変わる。
- ロックの状態はコンパイラが `__lock` で始まるフラグに直す（YAML の flags には書かない）。整合性チェックは、
  勾玉のつきつけ・「やめる」も操作として試す。`gaugeOut` のシーンはライフが尽きたときにだけ入るので、
  ゲームオーバーのシーンと同じく「たどり着かない」に出さない。

### ロックが先へ進むのを止める

元のゲームでも、ロックの印の付いた話題は選べる（選ぶとロックが現れる場面になり、探偵メニューへ戻る）。
先へ進めないのは、その人物の話題の表を解除の台本が切り替えるまで、同じ話題（印の付いたもの）しか出ないから。
YAML でも同じく、印の付いた話題の中身は「ロックが現れる」だけにし、続きの話題は解除のブロックで出す
（`when` に使うフラグを `breakLock` の後で set する）。

> 出典: 逆転裁判2 第2話（同じロックの、控えの間の話題）

```yaml
talk:
  - id: victim
    topic: 被害者のこと
    when: not unlocked         # 解除するまでは、この話題だけ
    locked: not unlocked
    then:
      - phoenix: "霧崎先生のこと、[wait 12]\n本当に知らないんですか?"
      - ini: "[speed 6]知りませんってばあ。[wait 12]\n[speed 5]意外としつこいんですねえ。"
  - id: victim2
    topic: 被害者のこと
    when: unlocked             # 解除のブロックで set: { unlocked: true }
    then: [ ... ]
```

- ロックが有効なまま `end`（クリア）に着く道があると、整合性チェック（TS 版・Rust 版の `--complete`）が
  「サイコ・ロック「lock0」を外さないまま、クリア（end）にたどり着けます」とエラーにする
  （コンパイラが `end` の前に、有効なロックがあれば `__lockend_ロックID` のシーンを通るようにしている。中身は `end` だけ）。
  章の中のロックは、どれも解除してからでないとクリアできないように書く。

## 証拠品を詳しく調べる

証拠品に `examine` を書くと、法廷記録でその証拠品の詳細を開いたときに「調べる」が出て、
調べる場所を選べる（元のゲームでは DS 版の第 5 話の、証拠品を 3D で回して調べる遊び）。
法廷記録を開ける場面ならいつでも使える: 探偵メニュー、つきつけの要求（`demand`）、台詞・日時の表示（`card`）・
選択肢の途中、証言（聞く・尋問）の途中。ただし `ui: { record: false }` で法廷記録を使えなくしている間は、台詞・
選択肢・証言の途中では使えない（探偵メニューとつきつけの要求では使える）。調べている間（`then` の中）は、
もう一度は調べられない。

> 出典: 蘇る逆転 第5話（弁護士バッジを詳しく調べる所。条件は読みやすく書き直した）

```yaml
evidence:
  badge:
    name: 弁護士バッジ
    description: ...
    examine:
      - spot: バッジのウラ       # 選択肢に出す場所の名前
        when: not badge_seen     # 条件を満たすときだけ選べる（省略可）
        then:
          - set: { badge_seen: true }
          - ema: "へえ‥‥[wait 20]バッジのウラって、\nこうなってるんですね!"
          - phoenix: "バッジには、ナンバーが\n刻まれているからね。"
      - spot: ...
        then: [ ... ]
```

場所の選択肢の最後には「やめる」が自動で付く。`then` が終わると調べ始めた場面に戻る。

- 台詞・日時の表示の途中からなら、その台詞に戻る（表示は、調べ始めたページを出し切った形で続きから）。
  選択肢・つきつけの要求ならその場面に、証言の途中なら同じ証言（聞く途中・尋問の同じ証言）に、探偵メニューなら探偵メニューに戻る。
- 表示（人物・背景・小窓・文字の枠など）と文中の `{evidence}` などは、調べ始めたときのものに戻す。
  フラグ・証拠品・人物ファイルの変化と、BGM、法廷記録を使えるか（`ui: { record }`）は、調べている間に変えたものが残る。
- `then` の中で `goto` / `investigate` したときは、戻らずにそのシーン・場所へ移る（調べた結果で話が進むとき）。
  調べ始めた場面（台詞の続きなど）は捨てる。尋問の途中からでも同じ（証言には戻らない）。

操作: 詳細を開いて右下の「調べる」をクリックするか E キー。

## 範囲を選ぶ

`pick` は、絵の上の範囲を選ばせるステップ（元のゲームでは DS 版の第 5 話の、指紋を検出する場所を選ぶ・映像の 1 点を
指し示すなどの遊び）。探偵メニューの外（会話・法廷）でも使える。書き方は場所の `examine`（[シナリオの書き方](scenario.md#場所探索編)）と同じく `area` と `then`。

> 出典: 蘇る逆転 第5話（探偵パート2、茜が指紋の検出をやって見せる場面。ID は読みやすく書き直した）

```yaml
- pick: 指紋を検出する所を選ぶ   # 案内（テキストの枠の 1 行目。空なら「どこを選ぶ？」）
  images: [bg128]               # 絵（背景のキー）。省略すると今の背景（スクロールした位置も調べると同じ）
  areas:                        # 選べる範囲。重なっていれば先に書いたもの
    - name: 指 1                # エディタ・報告での表示名（省略可）
      area: [70, 95, 28, 27]    # [x, y, 幅, 高さ]（絵・背景の座標）
      when: not dusted          # 条件を満たすときだけ選べる（省略可）
      then:
        - goto: dust_finger
    - name: 指紋
      area: [44, 121, 29, 23]
      when: dusted
      then:
        - goto: dust_print
  miss: [ ... ]                 # 範囲の外を選んだとき。終わると選び直す（省略すると範囲の外は選べない）
  quit:                         # 「やめる」を出す。選ぶと実行して次のステップへ（省略すると出ない）
    - goto: menu
```

- 範囲の `then` の後は、`choice` と同じく次のステップへ進む。`then` の中で `goto` すればそのシーンへ（選び直させるときも `goto`）。
- `images` を複数書くと、右下の早戻し・早送り（L・R キー）で絵を切り替えられる（元のゲームの映像の操作の代わり）。
  範囲に `image: 番号` を書くと、その絵を見せているときだけ当たる（省略するとどの絵でも）。
- 操作は探索編の「調べる」と同じ（クリックか、矢印キーで動かしたカーソルの所を Enter。目印も同じ）。「やめる」は左下か Esc。
  選んでいる間は法廷記録を開けない。整合性チェックは、範囲・範囲の外・やめるをすべて操作として試す。

## 人物を選ぶ

`nominate` は、並べた人物の顔から 1 人を選ばせるステップ（元のゲームでは DS 版の第 5 話の、指紋の照合と人物の指名で
共通の画面）。書き方はつきつけの要求（`demand`）と同じく `present` と `wrong`。

> 出典: 蘇る逆転 第5話（同じ場面の、検出した指紋の照合）

```yaml
- nominate: ""                            # 案内（画面の上に出す。空なら「だれを選ぶ？」）
  people: [gant, meekins, marshall, goodman, gumshoe, lana, ema, angel]  # 並べる人物 ID（8 人まで。4 人ずつ 2 段に、左上から順に）
  present:                                # 正解の人物（people のどれか）→ 選んだとき。then の後は次のステップへ
    gumshoe:
      - ema: "[speed 2]やっぱり!"
      - ema: "この指紋、[wait 16]イトノコ刑事さんの\nものだったんですね!"
  wrong:                                  # ほかの人物を選んだとき。終わるともう一度選ぶ（省略すると何もせず選び直す）
    - ema: "[speed 4]‥‥一致しませんでしたね。"
```

- 顔は人物ファイルの顔の絵（`profile.icon`）。絵がなければ名前のボタンにする。人物ファイルを持っているかどうかに関係なく、書いた人物を並べる。
- 操作はクリックか、矢印キーで選んで Enter。やめることはできない（元のゲームと同じ）。選んでいる間は法廷記録を開けない。
- コンパイルすると、人物ごとの範囲（DS 版の下画面の枠の位置）を持つ `pick` の命令になる。整合性チェックはすべての人物を操作として試す。

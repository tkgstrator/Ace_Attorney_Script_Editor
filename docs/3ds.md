# 3DS 版（逆転裁判5・6）の解析

自分で吸い出した 3DS のカードイメージ（`.3ds`）から、台本・BGM・効果音を取り出す。DS 版と違い、人物・背景は 3D モデルなので、
このエンジンで使うのは主に**台本と音声**。取り出したものは**配布しないこと**。

## ROM

`assets/roms/` に置く（gitignore 済み）。どれもファイル名がタイトル ID で、中の名前（ExHeader）と製品コードで見分けた。

| ファイル | 製品コード | 中の名前 | 作品 |
|---|---|---|---|
| `00040000000BAA00_v00.trim.3ds` | CTR-P-AGKJ | GS5 | 逆転裁判5 |
| `0004000000166A00_v00.trim.3ds` | CTR-P-BG6J | GS6 | 逆転裁判6 |
| `000400000014AD00_v00.trim.3ds` | CTR-P-BDGJ | GO | 大逆転裁判（扱わない） |

カードイメージは暗号化されたまま。復号には本体から吸い出した鍵のファイル `aes_keys.txt`
（`generatorConstant`・`slot0x2CKeyX`・`slot0x25KeyX` などの行）が要る。これも `assets/roms/` に置く。
5 は通常の鍵（slot 0x2C）、6 と大逆転裁判は 7.x 以降の鍵（RomFS と .code が slot 0x25）。

## 取り出し方

Rust 版（速い。2 本とも数秒で終わる）:

```sh
cargo build --release -p aa-ctr
target/release/aa-ctr assets/roms/00040000000BAA00_v00.trim.3ds --keys assets/roms/aes_keys.txt --out assets/extracted-rs/aa5
target/release/aa-ctr assets/roms/0004000000166A00_v00.trim.3ds --keys assets/roms/aes_keys.txt --out assets/extracted-rs/aa6
# 一部だけ: --only romfs,arc,script,audio（後の手順は前の手順の出力を読む）
```

| 出力 | 中身 |
|---|---|
| `exheader.bin`・`exefs/` | ExHeader と ExeFS（`code.bin` は BLZ で圧縮されたまま） |
| `romfs/`・`romfs.tsv` | RomFS のファイルそのまま（5 は 1861 個、6 は 3073 個） |
| `arc/`・`arc/index.tsv` | `.arc` を展開したもの。`arc/<.arc のパス>/<中の名前>.<種類>`（5 は 4827 個、6 は 5534 個） |
| `script/`・`index.tsv`・`commands.tsv` | `.gmd`（文章）を読める形にしたもの。`commands.tsv` は `<Ennn>` 命令の種類ごとの数 |
| `sound/`・`sound/index.json` | 音声を WAV（16 ビット、32728 Hz）にしたもの。`index.json` に長さとループの位置（秒） |

Python 版（`tools/rom/`、`uv run` で動かす。出力は `assets/extracted/aa5`・`aa6`）:

| スクリプト | 役目 |
|---|---|
| `ctr.py <rom> --keys <aes_keys.txt> <出力先>` | 復号して exheader・exefs・romfs を書き出す（`--info` で一覧だけ） |
| `mt_arc.py <romfs> <出力先>` | ARC の展開 |
| `mt_gmd.py <フォルダー…> --out <出力先>` | GMD を文章に。出力は Rust 版の `script/` と同じ（突き合わせ済み） |
| `mt_tex.py <フォルダー…> --out <出力先>` | テクスチャを PNG に（Rust 版には無い） |
| `mt_sound.py <フォルダー…> --out <出力先>` | ffmpeg で MCA を ogg に。6 の 58 本は ffmpeg が読めない（下の「音声」） |

RomFS・ExeFS・ARC・台本は、Rust 版と Python 版の出力がバイト単位で同じことを確かめた。

## 形式

どちらもカプコンの MT Framework（3DS 版）。細かい形式は各スクリプト・`crates/aa-ctr/src/` の各ファイルの先頭に書いた。

### ARC

`"ARC\0"`、版（5 は 0x10、6 は 0x11）、項目 0x50 バイト（名前 64 バイト、種類のハッシュ、圧縮後・展開後の大きさ、位置）。
中身は zlib。拡張子は中身の先頭 4 バイトから付けた（`tex`・`gmd`・`madp`・`mod`・`lmt`・`sdl`・`gui` など 29 種類）。

### 台本（GMD）

- 本編の台本は `romfs/script/_output/_sceNN_*_jpn.gmd`（5 は 688 個、6 は 952 個）。そのほかの文章（章の題、選択肢、法廷記録など）は
  `romfs/msg/` と ARC の中（`msg_cmn_jpn` など）にある
- 版 0x10201（5）は文を 2 つの 32 バイトの鍵で XOR してある。版 0x10302（6）は暗号化されていない
- 文は「ラベル（`L_LOAD`、`L_START` など、無いこともある）＋命令の混ざった文章」の並び。全体で 5 は 11,456 文、6 は 11,710 文
- 命令は `<E番号 引数…>` と `<PAGE>`・`<CNTR>`・`<RDFG n>` など（5 は 454 種類、6 は 501 種類）。多いものは
  `<E800 n>`（n が文の中で増えていくので、もとの台本の行番号と思われる）、`<E025 n>`（文字の速さと思われる）、
  `<E003 n>`（待ち）、`<E023><PAGE>`（ページ送り）
- 6 の `sce08` に、引数が全角数字の命令（`<E025 ８>`）が 4 か所ある。命令として数えている

```text
== 2 L_START
<RDFG 258><E800 37><E120 0>…<E042><CNTR>地方裁判所　第５法廷<E025 3><E005><E023><PAGE>
<E800 88>…<E041 4 2><E025 3>べ、<E003 16>弁護側、<E003 12>準備完了しています。<E023><PAGE>
```

`sceNN` の番号と話の対応はまだ確かめていない。6 は `msg/chapterN_jpn`（0 がクライン王国のプロローグ、5 が披露宴）と対応すると思われる。
5 のカードには `sce02` が無い（5 は 00・01・03・04・05・06、6 は 00〜04・06・08）。

### 音声（MCA / MADP）

- BGM・ボイス・長い効果音は `romfs/` の `.mca`、人物などの効果音は ARC の中の `.madp`（形式は同じ）。
  5 は 162 + 388 本（約 119 分）、6 は 378 + 572 本（約 149 分）。ループするものは `index.json` の `loop.start`〜`loop.end` を繰り返す
- 中身は DSP ADPCM（GameCube 系の 4 ビット ADPCM）。見出しのあとにマーカー（0x14 バイト）がいくつか並び、その後ろに係数が来る
  （マーカーの数: 版 4 = 5 は 0x28 の u16、版 5 = 6 は 0x28 の u32）
- ffmpeg は版 5 でマーカーのあるもの（6 の 58 本）を読めない。Rust 版は読める
- ffmpeg は ADPCM を丸めずに計算するので、DSP の標準の式（+1024 して丸める。Rust 版はこちら）と ±数の差が出る。
  ffmpeg と同じ式にすると ffmpeg の出力と全サンプルが一致することを確かめた（読み方そのものは正しい）
- 効果音の鳴らし方（`SBKR`・`SRQR`、台本の命令との対応）はまだ調べていない

### テクスチャ（TEX）

8×8 のタイルの中が Z 順の 3DS の並び。形式は RGBA8・RGB8・RGBA5551・ETC1・ETC1A4・A8・L8・LA8・A4・L4。
3DS のほかのゲームと違い、上下を戻さずに並べると正しい向きになる（文字の入ったテクスチャで確かめた）。キューブマップ（各作 2 個）は未対応。

## シナリオ YAML への変換（逆転裁判6）

```sh
bun tools/convert/ctr/index.ts --episode 1 [--stats]   # → assets/extracted/aa6/converted/ep1.yaml
bun run check assets/extracted/aa6/converted/ep1.yaml
```

エディタでは「公式 6（変換）」で開ける（絵と音はまだ 3DS 版のものが無いので、蘇る逆転のものを使う）。
第 1〜4 話は整合性チェックがエラー 0（最後まで通る）。第 5 話は探偵パートを探索編にしたため、チェックが状態の数で
終わらない（下の「探偵パート」）。変換の中身は `tools/convert/ctr/`。

- 話 N は `_sce{N-1}_c*` のファイルをファイル名の順につないだもの。ラベル 1 つが 1 シーン（`L_INIT`・`L_LOAD` は変換しない）
- 人物の ID は名前欄の番号（`NAME201` → `p201`）。人物ファイルの `cast201` も同じ番号で、ほぼそろっている
  （アウチ `NAME100` と亜内 `cast112` のようにずれる人がいて、今は別の人物になる）
- 法廷記録の増減は台本に無く、`_sceNN_preset` の表から「地点のファイルの終わりで加える」とした
- 正解が台本の外（ゲーム側の表・当たりの XFS）にある遊びは `tools/convert/ctr/games.ts` で読む。
  表は先に `tools/rom/mt_xfs.py` で JSON にしておく（使い方は games.ts の先頭）
  - 絵の 1 点を指し示す（`L_PO_*`）: `<E306 番号>` → `APP_PARAM_POINTOUT` → `hit/*.h2d` の当たり（512×256 の絵の座標）を
    `pick` にする。絵のキーは `evtcut_event0_02_0` の形（`UI/2_doc/22_evtcut/tex` の絵。プレイヤーへの割り当てはまだ）。
    絵の無いもの（3D の上面図）は `native` を残して解けたものとする
  - 霊媒ビジョン（`L_SPIRIT`）: `<E530 回>` の託宣（`spirit_jpn`）から「託宣を選ぶ → 感覚を選ぶ」の選択肢にする。
    正解は第 1 話の回 1・2 だけ分かっている（games.ts の ANSWERS）。ほかは解けたものとする
  - 証拠品を 3D で調べる（`L_INV`）: 調べる所を選択肢にし、名前はその所の最初の台詞から取る（外れがあれば「ほかの所」）
  - みぬく・映像の指し示し・箱の仕掛け: 解けたものとして成功の先へ
- 「相談する」（`L_ASSIST`）など、ボタンから入る場面は着けないシーンとして残る

### 台本の命令（推測）

| 命令 | 意味 |
|---|---|
| `<E041 役 名前>` / `<E260 役 名前>` | 台詞の始まり（名前は `name_jpn` の番号。E260 は証言）。空欄ならナレーション |
| `<E023><PAGE>` / `<E024>`・`<E027>` | ボタンを待つ / 待たずに進む |
| `<E003 n>`・`<E025 n>` | 待ち・文字の速さ |
| `<E005>`〜`<E008>` | 文字の色（白・赤・青・緑）。`<CNTR>` + 緑は日時・場所の表示 |
| `<E004 n>` / `<E039>` | 同じファイルの n 番目のラベルへ / 次のファイルへ |
| `<E221>` `<E222 文 ラベル>`… `<E223>` | 選択肢（文は 12 未満が `choice_common`、以上が `choice_sceNN` の `CHOICE{話}_{番号-12}`） |
| `<E028 a b>` / `<E029 a b>` / `<E030 a b 値 ラベル>` | フラグを立てる / 下ろす / 値なら飛ぶ |
| `<E604 n>` / `<E605>` | BGM を流す / 止める（番号と音声ファイルの対応はまだ） |
| `<E060 0 番号>` / `<E061>` | 証拠品を小窓で見せる / 消す |
| `<E240>` `<E241 隠す フラグ 証言 ゆさぶり 正解 外れ>`… `<E244 ラベル 種類 番号>` `<E242 ラベル>` `<E243>` | 尋問（exam.ts の先頭を参照）。`<E245 証言>` で隠れた証言を出す |
| `<E224 1 0>` `<E225 種類 番号 ラベル>` | 証拠品のつきつけ要求 |
| `<E279 n>` / `<E284 n>` / `<E285>` | ライフが減る予告 / 減らす / ゲームオーバー |
| `<E249 ラベル…>` | 外れの反応を乱数で選ぶ |

### 探偵パート（`tools/convert/ctr/invest.ts`）

物語のファイルの `<E386 背景 場所>` で行き来できる場所を並べ、`<E393 場所 ラベル>` で探偵パートに入る。場所は
`APP_PARAM_ID_SCRIPT_BG`（表 12）の番号で、その台本（`_sceNN_bgNNNN_*`）が探索編の場所（`places`）になる。
`<E394>` か、`<E392 バンク 番号>` で登録した終わりのフラグがすべて立つと、探偵パートを出る。

| 場所の台本の中 | 探索編 |
|---|---|
| 最初のラベル（`L_EVENT_CHECK`・`L_START`）と `L_TOPIC_INIT` | `enter` |
| `<E313 ? 部品 ラベル …>` | `examine`（位置は 3D の部品で取れないので、画面を縦に切った帯。名前はそのラベルの最初の台詞） |
| `<E377 人 話題 ラベル>`・`<E378 人 旧 新 ラベル>` | `talk`（話題の名前は `topic_sceNN` の（番号 − その話で最小の番号）番目。差し替えは同じ話題の版） |
| `L_THRUST_nn` の `<E224>`・`<E225>` | `present`・`presentWrong` |
| 話題で呼ぶ `<E033 11 番号 …>` の人物の台本（表 11） | `person` |

- 場所ごとの終わりの判定（`LABEL_0000` の `<E394>`）は `<場所>_done` のシーンにし、終わりのフラグが立つと話題の後に入る
- 出口（`<場所>_dtc_exit`）で、その探偵パートの場所で手に入る法廷記録をまとめて加える
  （物語のファイルをつなぐ近似なので、取らずに先へ進んで詰むのを防ぐ）
- `<E107 種類 番号 ?>` は法廷記録に加え、`<E106 種類 旧 新>` は差し替え。`<E101>` は章の頭に並ぶ持ち物を外す命令と思われるが、
  変換では native のまま
- 第 5 話: 場所 248・話題 962・調べる所 1804。探偵パートを 1 つ通るごとに整合性チェックの状態が約 5 倍になり、Rust 版
  （`--complete`、上限 3000 万でも）も TS 版も終わらない。第 2 話（場所 103）は 5 秒、第 3 話（171）は 80 秒。
  増える元は分かっていない（話題の数・法廷記録の差し替え・任意の話題が立てるフラグの後の分岐が疑わしい）。
  エディタでの編集・プレイ、`aa-verify`（既定の軽いチェック）は使える

### 「たどり着かないシーン」の警告を減らす変換（第 1〜4 話）

`aa-verify --complete` の警告は、第 1〜4 話で 76/166/718/108 件から 33/49/128/43 件になった（エラーは 0 のまま）。

- 場所の台本は話の全体で使い回されるので、L_TOPIC_INIT などが進み具合のフラグ（`f{バンク}_{番号}`）で話題を切り替えている。
  そのフラグを立てるのが、この探偵パートの物語のファイルより後のファイルだけなら、その枝と、そのせいで選べない話題は
  落とす（`prune.ts`、`index.ts` の `flagPossible`。ほかの台本（場所・人物・ほかの話）でも立てるフラグと、どこでも立てない
  フラグは立ちうるとして残す）。話題のフラグは、選べる話題の中でだけ立つと数えて固定点まで繰り返す
- 尋問の外れの反応 `<E022 使う ラベル …>` は `<E249>` と同じく乱数で選ぶ（L_TUKI_NG00〜02 が場面になる）
- 相談する（`L_ASSIST`）: ボタンで入る場面なので、証言をひと巡りしたところで「相談する / 続ける」を聞く
- みぬく・指し示すのうち外れの先が分かるもの（`KS_NG`、`L_PO_CHECK`）は、「正解する / はずれる」の選択肢にする
- 回想・まとめの写し（`<MCRS 種類 ? n>` の n が `L_KAISOU`・`L_MATOME`）は、本文にそのまま入っている台詞の写しなので、
  ほかから移ってくる場合を除いて場面にしない。霊媒ビジョンの中身（`_spirit_check`・`hint`・`no_hint`・`retry`）と空の場面は、
  移ってくる道が無ければ落とす（`index.ts` の `dropRedundant`）
- ゲームオーバー（`L_GAMEOVER`）は話のファイルごとにあるが、シナリオのゲームオーバーは 1 つ。ファイルの最初で
  `gameover_at` に番号を入れ、`gameover_by_file` で番号のものへ分ける。整合性チェックはライフが尽きない前提なので、
  ゲームオーバーの場面の警告（第 1〜4 話で 20/22/57/37 件）は残る
- 残り: 解けたものとしている遊び（`ks_p1_*`、`combo_start_com`、`po_box`、`pom_*`）、`chr_del`（人物を消す）、3 話の `c200_*`
  （台本の番号表で飛ぶ先）、3 話の場所の話題 30 件（場所の台本が自分で立てるフラグに依存する分岐）

## まだ分かっていないこと

- `sceNN` と話の対応、`c`・`bg`・`chr`・`q` などのファイル名の意味（`bgNNNN` は背景の番号と同じ形）
- 命令（`<Ennn>`）の意味。DS 版の台本の命令との対応
- 効果音のバンク（`SBKR`・`SRQR`）と、台本からの鳴らし方
- ムービー（`.moflex`、Mobiclip 400×240）は ffmpeg で読めるが、まだ変換していない

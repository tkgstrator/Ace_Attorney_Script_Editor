# シナリオの書き方

台詞の文体（カタカナ表記の使い分け）は [カタカナの表記](katakana.md) を参照。
画面（4:3、256×192 ドット）は [画面](screen.md) を参照（右にボタンの欄を足した 16:9 も試験的に選べる。画面の中は同じ）。

完全な例は [サンプル事件「時計塔の鐘」](../apps/player/cases/clocktower.yaml)。
ファイルの先頭に次の行を書くと、VS Code の YAML 拡張で補完と検証が効く。

```yaml
# yaml-language-server: $schema=../../../schema/scenario.schema.json
```

`bun run check <ファイル>` で、未定義の人物・証拠品・フラグ・シーンの参照や、
フラグの型の不一致を行番号付きで報告する。`--check-font` を付けると、DS 版フォントに
無い文字も報告する（言い換え候補つき。詳しくは [カタカナの表記](katakana.md)）。

## 全体

蘇る逆転 第1話の人物・証拠品で書いた例（値は短くし、`parts` は探偵パートのある話の形にしたもの）。

```yaml
id: ep1                   # セーブデータの識別に使う
title: はじめての逆転
player: phoenix           # ゆさぶる・つきつけるときの掛け声の主
life: 5                   # ライフの最大値（既定 10。10 以下は「！」の数、超えると棒のゲージで出す）
defaults:
  penalty: 1              # penalty: true で減る量（既定 2）
  wrongPresent:           # 見当違いの証拠品をつきつけたときの既定の反応
    - judge: その「{evidence}」が、どう関係するのですかな？
    - penalty: true
characters:
  phoenix:
    name: ナルホド
    stand: defense          # 背景の選択に使う
  mia:
    name: チヒロ
    profile: { name: 綾里 千尋, age: 27, description: ぼくの上司。 }   # 法廷記録の人物ファイルに載る（なければ載らない）
evidence:
  badge: { name: 弁護士バッジ, description: ... }
  autopsy: { name: 高日美佳の解剖記録, description: ... }
  dye:
    name: 舞台用の染料
    description:            # 配列にすると、フラグで説明が切り替わる（人物の profile.description も同じ）
      - when: dye_detail    # 条件式（if / when と同じ書き方）
        text: タンクの水を青くする。薄めて使う。
      - text: タンクの水を青く染めた物。   # when を省くと、いつでも満たす（最後に置く既定）
flags:                    # フラグ名: 初期値（型は初期値から決まる）
  dye_detail: false
  pressed_door: false
  mistakes: 0
start:
  scene: opening
  evidence: [badge, autopsy]
gameover: guilty          # ライフが尽きたときのシーン（省略時は組み込みの画面）
parts:                    # 章を探索編・裁判編に分ける（下の「編」を参照）
  - id: investigation
    kind: investigation
    title: 探偵パート
    scenes: { ... }
    places: { ... }
  - id: trial
    kind: trial
    title: 法廷パート
    scenes: { ... }
```

説明を配列にすると、上から条件を調べて、満たす最初の説明を出す（法廷記録も、証拠品を加えたときの詳細の窓も同じ）。
ID は変わらないので、法廷記録の位置やつきつけの正解はそのまま。書き加えたことは台詞で知らせる。
条件式の未定義のフラグは、ほかの `when` と同じく報告される。

1 つの YAML ファイルが 1 つの章（事件）。編に分けないときは、`parts` の代わりにトップレベルに
`scenes:` を書く（全体が 1 つの裁判編になる）。

## 編（探索編・裁判編）

`parts` には編を順に並べる。シーンと場所の ID は、編をまたいで章の中で重ならないようにする
（`goto` は編をまたいで移動できる）。会話シーンの最後に移動がなければ、次に書かれたシーンへ進む（編をまたいでも同じ）。

- `kind: investigation`（探索編）: `scenes` と `places`（場所）を書ける
- `kind: trial`（裁判編）: `scenes` だけ

### 場所（探索編）

`- investigate: 場所ID` でその場所へ行き、探偵メニュー（調べる・移動する・話す・つきつける）を出す。
各行動のブロックが終わると、その場所の探偵メニューに戻る。探索編を終えるには、ブロックの中で `goto` する。

> 出典: 逆転裁判2 第2話（探偵パート1 の倉院の里。ID と条件は読みやすく書き直した）

```yaml
places:
  village:
    name: 倉院の里              # 「移動する」の一覧や、画面左上に出す名前
    background: bg255          # 背景のキー（省略すると場所の ID）
    examineScroll: true        # 「調べる」の間に背景をスクロールできるか（true / false か条件式。省略すると true）
    person: maya               # その場所にいる人物。条件で変えるなら [{ id: maya, when: 条件 }, { id: lotta, when: 条件 }]
    enter:                     # 来たときに毎回実行する
      - if: not visited(village) # 初めて来たときだけ（探偵メニューに着いた時点で訪問済みになる）
        then: [ ... ]
    examine:                   # 調べる。area は背景の上の [x, y, 幅, 高さ]（背景の座標。横長の背景なら x は 0〜511）
      - id: bus_stop           # 調べた印の ID（省略すると village_examine1, 2, ...）
        name: バス停            # エディタでの表示名
        area: [38, 82, 34, 62]
        then:
          - phoenix: "古びたバス停だ。"
    examineDefault: [ ... ]    # 何もない所を調べたとき（省略すると「特に気になるものはない。」）
    talk:                      # 話す（その場所の人物と）
      - id: request            # 話した印の ID（省略すると village_talk1, 2, ...）。話し終えた話題には印が付く
        topic: 今日の依頼
        then: [ ... ]
      - topic: 倉院の里
        when: seen(request)    # 条件を満たすと話題に出る
        then: [ ... ]
    present:                   # つきつける（その場所の人物に）。探索編なので「くらえ！」は出ない
      badge: [ ... ]           # 証拠品 ID
      lotta: [ ... ]           # 人物 ID（人物ファイルをつきつけたとき）
    presentWrong: [ ... ]      # ほかの証拠品・人物ファイル（省略すると「特に反応はなかった。」）
    move:                      # 移動する
      - training_hall
      - to: office
        when: seen(request)
```

探偵メニューの操作: ボタンはクリックか ←→ と Enter。「調べる」ではクリックした所か、
矢印キーで動かしたカーソルの所を Enter で調べる。Esc で探偵メニューに戻る。X で法廷記録。

画面（256×192）より大きい背景（横長の 512×192 など）の場所では、DS 版と同じく「調べる」の間に背景をスクロールできる。
右下の矢印のボタンか L キー（DS 版の L ボタン）で、背景が左端と右端の間を 1 フレーム 6 ドットずつ動く
（左端なら右へ、右端なら左へ。動いている間は操作できない。人物も背景と一緒に動く）。矢印キーはカーソルを動かすだけ。
`area` は背景の座標なので、画面の点に背景の今の位置を足した点で当たりを調べる。
`examineScroll` が偽のときは動かせない（DS 版では地下駐車場の一部の場面だけ）。
背景の最初の位置（横長の背景は右端から始まるものなど）は背景ごとに決まっていて、台本の `scroll` で動かした位置も
「調べる」に引き継ぐ。「調べる」で動かした後は、それより前の `scroll` の動きは続かない（新しい `scroll` は効く）。

探索編の「つきつける」では、証拠品のほか人物ファイルも見せられる（DS 版と同じ。法廷記録の右上のタブか Tab キーで
人物ファイルに切り替える）。`present` に人物 ID を書くとその人物ファイルの反応になり、書いていない人物ファイルは
証拠品と同じく `presentWrong`（`{evidence}` には人物ファイルでの表示名が入る）。
証拠品 ID と人物 ID が同じものは、`present` のキーに書けない（どちらか分からないため。エラーになる）。

### サイコ・ロック・証拠品を詳しく調べる・範囲を選ぶ・人物を選ぶ

逆転裁判2・3 のサイコ・ロック（`psycheLock`）と、DS 版の第 5 話の「証拠品を詳しく調べる」（証拠品の `examine`）・
絵の上の範囲を選ぶ（`pick`）・人物の顔から選ぶ（`nominate`）は [遊びの書き方](scenario-games.md) を参照。

## シーン

シーンには「会話」と「証言」の2種類がある。

会話シーンはステップの配列。最後に `goto` / `end` / `gameover` がなければ、
YAML で次に書かれたシーンへそのまま進む。

```yaml
scenes:
  opening:
    - judge: "これより、矢張 政志の\n法廷を開廷します。"
    - goto: t1
```

証言シーンは、証言 → `after` → 尋問 の順に進む。尋問で最後の証言を過ぎると `loop` を実行して先頭へ戻る。

> 出典: 蘇る逆転 第1話（法廷パートの最初の証言）

```yaml
  t1:
    testimony: 事件の当日、目撃したこと   # タイトル
    witness: sahwit
    statements:
      - id: door                  # 省略すると s1, s2, ...
        text: "男はあわてていて、ドアを半開きに\nしたまま、行ってしまいました。"
        press:                    # ゆさぶり。終わると次の証言へ
          - phoenix: "[speed 5]半開き‥‥[wait 15][speed 3]ですか。"
          - set: { pressed_door: true }
      - id: time
        text: "時間はハッキリ覚えております。\nお昼すぎの、2時でした。"
        present:                  # 証拠品 ID → つきつけたとき。goto しなければ同じ証言に戻る（人物 ID は下を参照）
          autopsy:
            - goto: contradiction
      - text: ...
        when: pressed_door        # 条件を満たすと証言に現れる（この証言には無い。書き方の例）
    after: [ ... ]                # 証言を聞き終えてから尋問に入るまで
    loop: [ ... ]                 # 最後の証言を過ぎたとき
    wrong: [ ... ]                # defaults.wrongPresent を上書き
```

逆転裁判2・3 のように尋問で人物ファイルもつきつけるときは、証言の `present` に人物 ID を書く（書いた証言では
人物ファイルもつきつけられ、書いていない人物ファイルは `wrong`。書いていない証言では蘇る逆転と同じくつきつけられない）。
ゆさぶりの前には「待った！」、つきつけの前には「異議あり！」が自動で入る。
吹き出しを出すときは効果音 `shout_objection` / `shout_hold` / `shout_takethat` を、ライフが減るときは `damage` を自動で鳴らす
（その ID の音が用意されていなければ鳴らない）。

## ステップ

| 書き方 | 意味 |
|---|---|
| `- phoenix: 台詞` | 台詞（省略形）。`（ ）` で始まると心の声として青字になり、立ち絵は切り替わらない |
| `- say: phoenix`<br>`  text: 台詞`<br>`  color: orange` | 台詞（完全形）。color は white / blue / green / orange / red |
| `- narrate: 文` | ナレーション（名前欄なし） |
| `- set: { flag: true }` | フラグに値を入れる |
| `- add: { mistakes: 1 }` | 数値フラグに加算 |
| `- give: autopsy` / `- take: autopsy` | 証拠品を加える / 外す（配列も可） |
| `- if: 条件`<br>`  then: [...]`<br>`  else: [...]` | 条件分岐 |
| `- choice:`<br>`    - text: 選択肢`<br>`      when: 条件`<br>`      then: [...]` | 選択肢。then の後は次のステップへ進む |
| `- demand: 問いかけ`<br>`  present: { autopsy: [...] }`<br>`  wrong: [...]` | 証拠品のつきつけ要求。不正解なら wrong の後にもう一度。裁判編なら、つきつけた後に「くらえ！」が自動で入る（探索編では入らない）。present に人物 ID を書くと、人物ファイルもつきつけられる（`profiles: true` なら、正解が証拠品だけでも人物ファイルを見せられる。人物ファイルの見当違いも wrong） |
| `- pick: 案内`<br>`  areas: [{ area: [...], then: [...] }]`<br>`  miss: [...]` | 絵の上の範囲を選ぶ（[範囲を選ぶ](scenario-games.md#範囲を選ぶ)） |
| `- nominate: 案内`<br>`  people: [a, b, c]`<br>`  present: { b: [...] }`<br>`  wrong: [...]` | 人物の顔から 1 人を選ぶ（[人物を選ぶ](scenario-games.md#人物を選ぶ)） |
| `- goto: scene` | シーン移動 |
| `- penalty: true` / `- penalty: 3` | ライフを減らす。0 になると gameover シーンへ（サイコ・ロックの挑戦中は gaugeOut のシーンへ） |
| `- penalty: risk` / `- lifeRisk: 10` | lifeRisk で予告した量（ゲージの点滅）だけ減らす / 減る量を予告する（0 で消す） |
| `- heal: 40` / `- heal: true` | ライフを回復する（true は最大まで。最大は超えない） |
| `- shout: objection`<br>`  by: payne` | 吹き出し（objection / hold / takethat）。by の既定は player |
| `- banner: 文` | 画面中央の大きな文字（「無罪」など） |
| `- card: "日時\n場所"` | 日時・場所の表示。画面を暗くし、テキストウィンドウに緑字で中央寄せ（[下の例](#日時の表示と選択肢の例)） |
| `- showEvidence: badge` / `- showEvidence: null` | 画面左上の小窓に証拠品を見せる。シーンが変わると消える |
| `- show: maya` / `- show: null` | 表示する人物を切り替える |
| `- location: bg9` / `- location: null` | 場所（背景）を変える。null で法廷（立ち位置で背景が決まる）に戻る |
| `- scroll: { x: -6 }` / `- scroll: null` | 画面より大きい背景を 1 フレームごとに x・y ドット動かす（端で止まる。人物も一緒に動く）。背景を変えると最初の位置に戻る |
| `- investigate: village` | 探索編の場所へ行き、探偵メニューを出す |
| `- bgm: trial`<br>`  frames: 60` / `- bgm: null` | BGM を流す（繰り返し）/ 止める。frames はフェードの長さ。セーブデータに残り、ロードすると流れ直す |
| `- se: gavel` | 効果音 |
| `- shake: true`<br>`  strength: 1` | 画面を揺らす。`shake: 40` で長さ（既定 30）。strength は 0〜2（既定 0） |
| `- flash: true` / `- flash: red` | 画面を一瞬光らせる（true は白。frames で長さ（フレーム）。省略すると既定の 3） |
| `- fade: out`<br>`  color: white`<br>`  frames: 48` | フェードアウト（画面を覆う）。`fade: in` で明ける。覆っている間の台詞は覆いの上に出る。color の既定は black、frames の既定は 30 |
| `- wait: 30` | 待つ |
| `- fade: out`<br>`  nowait: true` | 終わるのを待たずに次へ進むフェード（元のゲームのフェード） |
| `- bgmPause: true` / `- bgmPause: false` | BGM を一時停止する / 続きから再開する（frames でフェード） |
| `- textbox: false` / `- textbox: true` | 文字の枠を隠す / 出したままにする（書かなければ台詞のときだけ出る） |
| `- ui: { record: false, life: true }` | 法廷記録を開けなくする・ライフを出す（life: null で既定に戻す）。`locks` はサイコ・ロックの錠の表示 |
| `- giveProfile: w` / `- takeProfile: w` | 人物ファイルに加える / 外す。最初の顔ぶれは `start.profiles`（省略すると profile のある全員） |
| `- resume: stay` | 尋問のゆさぶり・つきつけのブロックから、同じ証言（stay）・次（next）・最初（first）へ戻る |
| `- show: phoenix`<br>`  talk: 15`<br>`  idle: 14` | 人物と動き（元のゲームの動きの番号）。文字送りの間は talk、止まっている間は idle |
| `- native: bg_scroll`<br>`  args: [2, 1, 10, 190]` | 元のゲームの命令で、まだ対応していないもの（何もしない。変換で失わないために残す） |
| `- end: true` / `- gameover: true` | クリア / ゲームオーバー |

台詞には `auto: true`（出し終えたらボタンを待たずに進む）、つきつけの要求には `by: judge`（問いかける人物）を付けられる。
`defaults.autoShow: false` にすると、台詞で話し手の立ち絵に切り替わらなくなる（表示は show だけで変わる。元のゲームと同じ）。
人物に `pose: { talk: 85, idle: 84 }`（元のゲームの動きの番号）を書くと、`show` で動きを指定していないときの立ち絵になる
（話している間は talk、それ以外は idle）。手元で DS 版の絵を取り出してあれば、オリジナルの人物にも公式の人物の絵を借りられる
（例は [サンプル事件「仮面の奇術師」](../apps/player/cases/masked.yaml) の `characters`）。
主人公（`player`）の立ち絵は、元のゲームと同じく法廷でだけ出る。`location` で背景を変えている間（控え室・探索編の場所）は、
主人公が話しても立ち絵は切り替わらず、相手の立ち絵のままになる。

時間の単位はすべてフレーム（1/60 秒）。元のゲームの台本と同じ。

### 日時の表示と選択肢の例

> 出典: 蘇る逆転 第1話（法廷パートの始まりの日時の表示と、被告人の名前を問われる所）

```yaml
- card: "8月3日　午前10時\n地方裁判所　第2法廷"
- judge: "まず、[wait 12]この事件の[color red]被告人[color white]の名前を。\n[wait 30]‥‥言ってみなさい。"
- choice:
    - text: 成歩堂 龍一
      then: [ ... ]            # 裁判長に聞き直されて、同じ問いへ goto で戻る
    - text: 矢張 政志
      then: [ ... ]            # 正解。then の後は次のステップへ
```

## 条件式

`if` / `when` に書く。

```
pressed_door and not hint_given
mistakes == 0 || life >= 5
has(autopsy)         # 証拠品を持っているか
visited(t1)          # シーン・場所を訪れたか
seen(request)        # 探索編で、その「調べる」「話す」をしたか
```

- 演算子: `and` `or` `not`（`&&` `||` `!` も可）、`==` `!=` `<` `<=` `>` `>=` `+` `-`
- `life` は現在のライフ
- YAML では行頭の `!` がタグとして解釈されるので、否定には `not` を使う

## 画面

DS 版のメイン画面（上画面）と同じ 256×192 ドットで描く。DS では下画面にあった選択肢・法廷記録・
「ゆさぶる」「つきつける」は、メイン画面の上に重ねて出す。
`give` で証拠品を加えると、次の台詞の間だけ画面上部に証拠品の詳細が出る。

## テキスト枠

台詞は 1 行 全角16字 で自動的に折り返し、2 行ずつ表示する。
収まらない台詞は自動でページが分かれ、クリックで続きを表示する。
好きな位置で改行したいときは `\n` を書く（YAML では `"..."` で囲んだ文字列の中で使う）。

> 出典: 蘇る逆転 第1話（被告人の名前を問われる所）

```yaml
- mia: "ヒコクニンっていうのは、[wait 8]裁判に\nかけられている人のことよ!"
```

行数と字数は `Player` の `charsPerLine` / `linesPerPage` で変えられる。

## 台詞の途中の演出

元のゲームの台本と同じく、台詞・証言・ナレーションの途中に演出を書ける。その文字が出るところで実行する。

> 出典: 蘇る逆転 第1話（被告人の名前を問われる所）

```yaml
- mia: "な、[wait 5][flash][se SE019][shake 30 1][speed 2]なるほどくん!"
- mia: "あなたは、[wait 10][color red]弁護人[color white]!"
```

| 書き方 | 意味 |
|---|---|
| `[wait 8]` | 待つ（フレーム） |
| `[speed 2]` | 1 文字を出す間隔（フレーム、既定 3） |
| `[color red]` | ここからの文字の色（white / blue / green / orange / red） |
| `[shake 30 1]` | 画面を揺らす（長さ、強さ 0〜2。省略すると 30、0） |
| `[flash]` / `[flash red 8]` | 画面を光らせる（色、長さ） |
| `[se damage]` | 効果音 |
| `[bgm trial 60]` / `[bgm null]` | BGM の切り替え（フェードの長さ） |
| `[show w 224 225]` / `[show null]` | その文字のところで人物を切り替える（話す動き・黙る動き） |
| `[location bg5]` | その文字のところで背景を切り替える |
| `[native name 1 2]` | 未対応の元の命令（何もしない） |
| `[blip typewriter]` / `[blip off]` / `[blip on]` | 文字送りの音の種類を変える（male / female / typewriter）・止める・戻す |

文字送りの音は、話し手の `blip`（male / female / typewriter / none、既定 male）で決まる。日時・場所の表示はタイプライター。
元のゲームと同じく、標準の速さでは 1 文字おき、速さ 5 以上とタイプライターでは毎文字鳴らす（最初の文字は鳴らさない）。
鳴らす音の ID は `blip_male` / `blip_female` / `blip_typewriter`。ページ送り（`ui_page`）・選択肢の移動（`ui_select`）・決定（`ui_decide`）も自動で鳴る。

- `[` を文字として書くときは `[[`
- `[` で始まる台詞は、YAML では `"..."` で囲む（囲まないと配列と解釈される）
- 句読点のあとの自動の間は、元のゲームにはないので既定では入らない。手書きのシナリオで入れたいときは
  `defaults.autoPause: true`

## 文中の差し込み

台詞などの `{名前}` は、フラグの値や `{life}` に置き換わる。
つきつけの不正解ブロックの中では `{evidence}` がつきつけた証拠品の名前になる。

## 音

BGM・効果音の ID に何を鳴らすかは、ゲーム側（`Player` の `audio`）で決める。
`createAudio({ bgm: id => URL, se: id => URL })` で、ID から音声ファイルの URL を返せばよい。
プレイヤーは `apps/player/src/sounds.ts` で、その場で合成した仮の音を使っている。
手元で DS 版の音を取り出してあれば、`BGM013`・`SE010` のような公式の番号をそのまま書ける。番号と役割の対応は
[公式の BGM・効果音の番号](writing/sounds.md)。
ブラウザは利用者の操作があるまで音を出さないため、最初のクリック・キー入力の前の BGM はその後で流れ始める。

## 整合性チェック

`bun run check <シナリオ.yaml>` は、書き方の検証の後に、エンジンで選べる操作（文章送り・選択肢・つきつけ・ゆさぶり・
調べる・移動する・話す）をすべて試して、次のものを報告する。

- **詰み**（エラー）: どう操作しても終わり（`end` か `gameover`）にたどり着けなくなる場面。
  例: 探索編で手に入らない証拠品を、法廷のつきつけで求めている／探索編から出る条件を満たせない。
  足りない証拠品があれば、その名前も出す
- **クリアできない**（エラー）: どう遊んでも `end` にたどり着けない
- **到達しないもの**（警告）: どう遊んでもたどり着かないシーン・場所、選べない話題・調べる所

ライフは減らないものとして調べる（ライフが尽きてのゲームオーバーは正しい動きなので、詰みに数えない）。
乱数で飛ぶ所（`random`）は、すべての行き先を試す。証拠品を詳しく調べる操作も試す。
見当違いのつきつけは 1 つだけ試す（証拠品から選び、証拠品がすべて正解のときだけ人物ファイルから）。

詳しく調べる操作は、状態を変えうる場所（フラグ・証拠品・人物ファイル・法廷記録の鍵を変えるか、別のシーンへ移るもの）だけを試す。
台詞・日時の表示・証言を聞く途中では、次のどれかなら試さない（どれも近似ではないので、結果は同じ）。

- 表示だけが続くかたまりの途中の台詞（最後の台詞で試す）
- 調べる場所で読み書きする変数と、次に調べられる所（次の台詞・選択肢・つきつけの要求・探偵メニュー）までの命令で読み書きする
  変数が重ならない（次の所で試すのと同じ結果になる）。別のシーンへ移る場所は、間の命令が書く変数が移る先で読まれないとき
- 実際に試しても状態が変わらない（すでに調べ終えている）

状態が増えすぎないよう、この先の動きに関係しない違いは区別しない（どれも近似ではないので、結果は同じ）。

- 表示（立ち絵・背景・BGM など）・ライフの違い（人物ファイルは、人物ファイルをつきつけられる所がなければ区別しない。
  法廷記録を使えるかは、詳しく調べられる証拠品がなければ区別しない）
- その地点から先で読まれない（読む前に必ず書き直される）フラグ・visited・seen。例: 探偵パートで立てた話題のフラグは、
  次の法廷パートでは区別しない
- 値によって結果の変わらない条件の変数。例: `(not a and b) or (not a and not b)` の `b`、
  「初めて来たか」のフラグで初回だけ台詞を出してフラグを立てる `if`（出口ではどちらもフラグが立っている）
- 数値のフラグの、条件式で比べている値の範囲の外（足し算やほかのフラグとの比べに使うフラグは、値をそのまま区別する）

文章送りしかできない場面は、選ぶ場面までまとめて進める。同じ場面で同じ操作をして、途中で読んだ変数の値も同じなら、
前の結果を使い回す。状態が 300 万個（`--limit` で変えられる）を超えると途中でやめ、その旨を出す。

Rust 版（`crates/aa-verify`）は同じ報告を速く出し、編ごとに分けて調べるので第 5 話の規模でも 2 分ほどで終わる。
既定は近似の軽いチェック（つきつけの証拠品を持てるか・シーンに着けるか・フラグを立てられるか）で、
網羅的に調べるときは `--complete` を付ける。何を調べて何を調べないかは [整合性チェックの説明](../crates/aa-verify/README.md) を参照。

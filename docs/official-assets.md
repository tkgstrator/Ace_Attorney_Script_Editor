# 公式の画像アセットの仕様（DS 版の蘇る逆転・2・3）

自作の素材を「DS 版の逆転裁判の見た目」に合わせるための、公式の絵の**形式と数値だけ**のまとめ。
公式の絵・台詞・切り抜いた画像は、この文書にもリポジトリにも入れない（数値の JSON だけを置く）。

- 数値の出どころ: `tools/assets/measure.py` の出力 `tools/assets/official-assets.json`（作り直し方は §6）。
- 種類ごとの詳しい表:
  - [背景・法廷のパン・机](official-assets/backgrounds.md)
  - [人物・吹き出し・カットイン・重ね絵・サイコ・ロック](official-assets/objects.md)
  - [法廷記録・名札・下画面の UI・テクスチャ・フォント](official-assets/record-ui-font.md)
- 人物の立ち絵の細かい決まり（線・影・動き・差分コマ）は [`tools/sprites/SPEC.md`](../tools/sprites/SPEC.md)、
  立ち位置は [`tools/sprites/STAND_SPEC.md`](../tools/sprites/STAND_SPEC.md)。この文書と重なる所はそちらが正。

表の「中央値（p10〜p90）」は、その種類の全部の分布。作品の違いが無いものは 1 つの値だけ書く。
蘇る逆転 = 蘇、逆転裁判 2 = 2、逆転裁判 3 = 3（どれも DS 版の日本語版）。

## 1. DS の画面の決まり

| 項目 | 決まり |
|---|---|
| 画面 | **256×192 ドットの画面が 2 枚**（上画面・下画面。下画面はタッチパネル）。1 ドット = 1 画素 |
| 描画の仕組み | 2D の描画エンジンが 2 つ（メインとサブ）。メインは 3D も描ける。どちらの画面にどちらを割り当てるかはゲームが決める |
| 層 | 1 画面に **BG（背景の層）4 枚**（BG0〜BG3）と **OBJ（スプライト）128 個**。BG・OBJ ごとに優先度 0〜3（0 が手前）。同じ優先度なら OBJ が BG より手前 |
| タイル | 絵はすべて **8×8 のタイル**の組み合わせ。BG はタイルの地図（反転つきで同じタイルを使い回せる）、OBJ はタイルの四角 |
| OBJ の大きさ | 8×8・16×16・32×32・64×64・16×8・32×8・32×16・64×32・8×16・8×32・16×32・32×64 の 12 種類だけ。大きな絵は OBJ を並べて作る |
| 色の形式 | **4bpp**（1 画素 4 ビット = 16 色のパレット 1 本から選ぶ）と **8bpp**（1 画素 8 ビット = 256 色のパレットから選ぶ） |
| パレット | BG 用 256 色・OBJ 用 256 色（画面ごと）。4bpp ではこれを **16 色 × 16 本**として使い、タイル（OBJ）ごとにどの 1 本を使うか選ぶ。拡張パレット（256 色 × 16 本）もある |
| 透明 | 各パレットの**色番号 0 は透明**（4bpp なら 16 本それぞれの 0 番）。実際に使える色は 4bpp で 1 本 15 色、8bpp で 255 色。一番奥で透明になった所は「背景色」（BG パレットの 0 番）が見える |
| 色の段 | **15 ビット色**（BGR555: 赤・緑・青 各 5 ビット = 各 32 段、全 32768 色）。8 ビットに直すと `c × 255 ÷ 31` のような 32 段の値だけになる |
| 半透明 | 画素ごとの透明度は無い（有るか無いかだけ）。層全体の半透明（アルファブレンド）と明るさの変化（フェード）はレジスタで行う。3D のテクスチャだけは画素ごとの透明度（A3I5 = 8 段・A5I3 = 32 段）を持てる |
| 3D のテクスチャ | 大きさは 8〜1024 の 2 のべき乗。形式は 4 色・16 色・256 色・A3I5・A5I3・4×4 圧縮・直接色。画素はタイルではなく**線形**（左上から 1 行ずつ） |

### 3 作品が DS の機能をどう使っているか

tools/rom の解析（`assets/extracted/README.md`・`tables/README.md`・`tables/bg_render.md`）と今回の計測から分かる範囲:

| 画面 | 使い方 |
|---|---|
| 上画面（**サブ**エンジン） | BG3 = 背景（256 色の設定、地図 512×256。横長・縦長はこの窓の中で動かす）、BG1 = 文字の枠、BG0 = 文字、BG2 = 2 枚目の背景・集中線など。OBJ = 人物（優先度 3）・法廷の机（優先度 3、人物より手前）・吹き出しや重ね絵（47 anim、多くは優先度 2）。重なりは 背景 → 人物 → 机 → 重ね絵 → 文字の枠 → 文字 |
| 下画面（**メイン**エンジン、3D あり） | ボタン・題の札などの文字は **OBJ（4bpp）**。法廷記録の一覧のアイコン・名前・説明文、移動先の小さな絵、場所の名前、大きな「▶」の板などは **3D のテクスチャ**（16 色・256 色）。暗い法廷の背景は BG |
| 色の出力 | 上画面は 5 ビットをそのまま 8 ビットにした色（`v × 255 ÷ 31`）。下画面（3D あり）は 6 ビットで出力され、`c6 = 2v + (v > 0)` → `c6 × 255 ÷ 63` の色になる（スクリーンショットと画素単位で一致） |
| 背景のパレット | 8bpp の背景は**色番号 32〜255（224 色）だけ**を使い、0〜31（パレット 0・1 = 文字と文字の枠）を空けている。4bpp の背景と法廷のパンは 16 色のパレット 1 本（パンはパレット 2 = 色番号 32〜47） |
| 人物・重ね絵 | すべて 4bpp の OBJ。部品ごとに 16 ビット単位の独自の RLE で圧縮。1 人のパレットは 1〜3 本 |
| 画面の大きさの前提 | すべて 256×192 の上画面に合わせて描かれている（人物・吹き出しの基準点は画面の中央 (128, 96)） |

## 3. 自作の素材を作るときの目安

方針: **DS の機械の制限（15 ビット色・16 色のパレット・8×8 のタイル）に合わせると、公式と同じ見た目になる。**
GBA 版は画面が 240×160 だが、色とパレットの決まり（15 ビット色・16 色のパレット・8×8 のタイル）は同じなので、GBA 風に寄せるときもこの目安でよい。

| 素材 | 目安 |
|---|---|
| 共通 | 15 ビット色に丸める（各色 `c × 255 ÷ 31` の 32 段）。透明度は 0 か 255 だけ。アンチエイリアス・ディザは使わない（線と影は `tools/sprites/SPEC.md` §3・§4） |
| 人物 | `tools/sprites/SPEC.md` に従う（256×192 のキャンバス、基準点 (128, 96)、1 人 15 色 + 透明、特有の動きだけ 2 本目まで） |
| ふつうの背景 | 256×192。簡単な絵は **15 色**（4bpp）、細かい絵（探偵パートの部屋など）は **224 色まで**（8bpp、公式は色番号 32〜255 を使う）。大きさは 8 の倍数 |
| 横長・縦長の背景 | 512×192 / 256×384。流すための絵なので、端から端まで続けて描く |
| 法廷の背景 | 弁護側・検察側・証言台は **15 色**。裁判長・全景は 224 色まで |
| パン | 1296×192。公式は左半分（648×192）だけを持ち、右半分は 8 ドットの列ごとに左右反転して作る。自作は 1296×192 を 1 枚で描いてよいが、色は 15 色にそろえる |
| 机 | 256×192 の透明の画像の、画面に出る位置に描く。**15 色以下**（公式 13〜14）。机の上の端は y=148（証言台 158） |
| 証拠品・人物ファイル | **64×64、15 色**（パレット 1 本）。公式はほぼ全部が四角いっぱいに描かれ、透明の所が無い（透明を使うのは 3% 未満） |
| 吹き出し | 256×192 の画面いっぱいの絵で **11〜15 色**、1 コマ |
| 重ね絵・小物 | 15 色以下（パレット 1 本）。大きさは 8 の倍数にすると OBJ に合う |
| 名札 | 48×16、6〜7 色 |
| 文字 | 16×16 のマスに 1 色で描き、送り 14。ふつうの字の点の範囲は幅 13・高さ 13（マスの x=1〜13、y=3〜15） |

- 大きさと部品の位置は **8 の倍数**にそろえるとタイル・OBJ に合う（公式の人物の部品の位置は中央値で 100% が 8 の倍数、3 は 93%）。
- 1 コマの OBJ の数は公式で最大 40 個前後（人物）。自作ではこの制限は無いが、細かく分けた絵ほど DS らしくない形にはならない。
- 今のプレイヤーの背景の素材の決まり（15 色）は `tools/sprites/SPEC.md` §2「人物以外」。

## 5. 分からなかったもの・確かめていないもの

- **ライフのゲージ（2・3）** と **サイコ・ロックの鎖**の絵は見つけられなかった（人物のパックにも 3D のテクスチャの一覧にも、それらしい物が無い）。
  錠そのもの（大・小）・解除の文字・光は人物のパックにあった。蘇の体力（「!」5 個）の絵の場所も調べていない。
- **法廷記録の小さいアイコン**: 下画面の一覧は 64×64 のテクスチャ（上画面のアイコンと同じ大きさ）で、別の小さい絵は無い。
  一覧で縮めて描いているかは確かめていない。
- 2・3 の下画面の UI 部品（OBJ）の表は解析されていないので、UI 部品の数値は蘇だけ。
- 2・3 の法廷記録の小さい字は、字形を切り出していないので数えていない。
- カットインが画面で拡大されるか、重ね絵の分類（どれが前景か）の細部。
- 前景は、机（OBJ）と重ね絵のほかに「背景の手前の層」（命令 77、BG2）があるが、形式は測っていない。

## 6. 数値の出どころと作り直し方

```sh
uv run python tools/assets/measure.py              # 3 作品 → tools/assets/official-assets.json
uv run python tools/assets/measure.py --games aa2  # 一部だけ（ほかの作品の値は残す）
uv run python tools/assets/measure.py --print      # 書かずに表示
```

- 入力: `assets/roms/` の ROM（読むだけ）と、tools/rom の抽出物 `assets/extracted/`（蘇）・`aa2/`・`aa3/`
  （`tables/*.json`・`record/`・`ui/`・`font/`・`script/`・`data/tail/index.tsv`）。抽出のしかたは `assets/extracted/README.md`。
- 背景・パン・机・人物のパック・3D のテクスチャ・本文の字は **ROM から直接**読む（パレットの大きさ・テクスチャの見出しで形式を確かめる）。
  アイコン・名前・説明文・名札・UI 部品は抽出した色番号の PNG（パレットは ROM のまま）から数える。
- 計測のコード: `tools/assets/m_bg.py`（背景・パン・机）、`m_obj.py`（人物のパック。組の分け方 `CATEGORIES` は一覧の絵を見て決めた）、
  `m_record.py`（法廷記録・名札・UI・テクスチャ）、`m_font.py`（フォント）、`common.py`（色の数え方・統計）。
- 人物のコマの細かい統計（線・差分コマ・動き）は `tools/sprites/official-stats.json`・`official-chars.json`（`tools/sprites/SPEC.md` の先頭）。
- 以前の担当の数値との違い: 「裁判長席は作品により 15 色か 207〜224 色」は、3 作品とも同じ 8bpp の絵で **209 色**だった
  （4bpp の裁判長席は見つからなかった）。「その他の背景は約 6 割が 15 色」は台本で使うものに限ると 51〜59%（全行では 53〜64%）。

# aa-verify（整合性チェック・Rust 版）

シナリオ（YAML）が最後まで遊べるかを調べる道具。`packages/script/src/verify.ts`（TS 版）と同じ報告を、速く・少ないメモリで出す。

```
aa-verify [--complete] [--limit 状態の数] [--json] <シナリオ.yaml | IR.json> ...
```

YAML を渡すと、`bun packages/script/src/export-ir.ts` でコンパイル済みの形（IR）にしてから調べる。
`bun packages/script/src/cli.ts <yaml> --engine rust` でも使える（`--light` で軽いチェック）。

## 2 つのモード

| | 軽いチェック（既定） | `--complete` |
|---|---|---|
| 調べ方 | 状態を区別せず、シーンの繋がりの上で目標から後ろ向きにたどる近似 | エンジンで選べる操作をすべて試し、たどり着ける状態を網羅する |
| 速さ | どの話も 0.1 秒以下 | 第 5 話で約 100 秒・約 680 MB |
| 見落とし | ある（状態の組み合わせで初めて起きる詰みは見つからない） | ない（下の「前提」の範囲で） |
| 誤検知 | まれにある | ない（見つけた詰みには再現手順がある） |

ふだんは軽いチェック、確実に調べたいとき（変換し直した後・公開の前など）は `--complete`。

## 軽いチェック（既定）が調べること

報告は項目ごと・編（parts）ごとに分けて出る。

1. **つきつけの証拠品を持てるか**
   - つきつけの正解（demand・尋問・探偵パートの present）の証拠品・人物ファイルを、その場面に着いた時点で持っている道があるか。
   - 人物ファイルは、証拠品と同じく「持っている」ものとして調べる（giveProfile・takeProfile・start.profiles）。
   - 詳しく調べるシーンへは、法廷記録を開ける場面（台詞・日時の表示・選択肢・証言・つきつけの要求・探偵メニュー）から入れるとする。
   - 持てないときは、理由を後ろ向きにたどって示す。理由は次のどれか。
     - give がない
     - give に着けない
     - 途中で取り上げられる
2. **シーン・場所に着けるか**
   - 各シーン・場所に、始まりから着ける道があるか。
   - 着けないときは、どの条件で止まるかを添える。
3. **フラグを立てられるか**
   - 条件式（when・if・移動・話題・調べる所）で読まれるフラグの値にする set が、着ける所にあるか。
   - 満たせない条件を報告する。

## `--complete` が調べること

始まりから、選べる操作（選択肢・つきつけ・ゆさぶり・移動・話す・調べる・詳しく調べる など）をすべて試す。
つきつけには人物ファイルも入る（探偵パートの人物と、人物ファイルを認めるつきつけの要求）。詳しく調べるのは、法廷記録を開ける
場面ならいつでも（台詞・日時の表示・選択肢・証言の途中も）。そうしてたどり着けるすべての状態について、次を報告する。

| 報告 | 重さ | 意味 |
|---|---|---|
| **詰み** | エラー | 始まりから着けるのに、そこからどう操作しても終わりに着けない状態。入る最初の場面を報告する。例: つきつけの正解を持っていない、探偵パートで移動先・話題・調べる所の条件が満たせずに先へ進めない |
| **クリアできない** | エラー | どう遊んでも `end` に着かない |
| **たどり着かないシーン・場所** | 警告 | どう遊んでも一度も入らないシーン・場所 |
| **選べない話題・調べる所** | 警告 | どう遊んでも一度も選べない話題・調べる所 |
| **打ち切り** | 警告 | 状態が `--limit`（既定 300 万）を超えた。結果は不完全 |

「終わり」は、`end` またはシナリオに書いた `gameover` を指す。

### 前提（ここに入らないものは調べない）

- **ライフは減らないものとして調べる。** ライフが尽きてのゲームオーバーは正しい動きなので、詰みに数えない。ライフが尽きたときのシーンは「たどり着かない」にも出さない。
- **`random` は、すべての行き先を試す。**
- **見当違いのつきつけは 1 つだけ試す。** どの証拠品・人物ファイルでも同じ反応になるので、それで十分。
  証拠品から選び、証拠品がすべて正解のときだけ人物ファイルから選ぶ（例: 第 5 話 p17_s022 は、人物ファイルでしか着けない）。
- **詳しく調べるのは、状態を変えうる場所だけを試す。** 状態（フラグ・証拠品・人物ファイル・法廷記録の鍵）を変えず、別のシーンへも
  移らずに戻るだけの場所は試さない。台詞・日時の表示・証言を聞く途中では、さらに次のどれかなら試さない（止まらずに進める）。
  - 表示だけが続くかたまりの途中の台詞（かたまりの最後の台詞で試す）
  - 調べる場所で読み書きする変数と、次に調べられる所（次の台詞・日時の表示・選択肢・つきつけの要求・探偵メニュー）までの
    命令で読み書きする変数が重ならず、試すと元の場面に戻る（次の所で試すのと同じ状態になる）
  - 試すと別のシーンへ移り、その場所が読む変数を間の命令が書かず、間の命令が書く変数が移る先で死んでいる（`defer.rs`）
  - 試しても状態が変わらない（すでに調べ終えている。結果は、調べるシーンで読み書きする変数の値ごとに覚える）
  どれも近似ではない（試さない調べ方の結果は、次の所で試す結果か、今の状態と同じになる）。
- **「調べる」は、範囲の重なり方の組み合わせごとに 1 点を試す。** 結果が変わりうる点はすべて試している。
- **状態の区別は、この先の動きに関係するものだけで行う。**
  - 表示（立ち絵・背景・BGM など）・ライフ・もう読まれないフラグは区別しない。
  - 人物ファイルは、人物ファイルをつきつけられる所がある章だけ区別する（証拠品と同じく、生きているものだけ）。
    法廷記録を使えるか（ui の record）は、詳しく調べられる証拠品がある章だけ区別する。
  - 値によって結果が変わらない条件の変数も区別しない。
  - どれも近似ではなく、詰み・到達しないものの判定は変わらない。

### 調べないもの

- 台詞の中身、表示・演出・音が正しいか。
- ゲームとして妥当か（ヒントが足りるか、など）。
- セーブ・ロード。
- シナリオが元のゲームと同じ動きか。変換済みの章で DS 版だけの遊びは、変換で選択肢に置き換えているので、その近似の範囲でしか調べていない。対象は指紋・字を書く・人物の指名など。

## 編ごとの探索

`--complete` は、編（探偵パート・法廷パートなど）ごとに分けて調べる。

- 編に入った状態の集まりから探索し、別の編のシーンに入ったら、そこを「出口」として止める。
- 出口の状態は重複を除いて、次の編の入り口に渡す。持ち越す証拠品・フラグもそのまま渡す。
- 行き来のある編（2 つの編に分かれた探偵パートなど）は、1 つのまとまりにして調べる。
- 編ごとに「この編でもう持っていない証拠品」などが分かり、区別する変数が減る。そのため、状態の数が「編同士の掛け算」ではなく「編ごとの足し算」に近くなる。
- 詰みは、編をまたぐ辺もつないだ全体で判定する。報告は編ごとに分けて出す。
- `--whole` を付けると、分けずに調べる（確かめ用）。

## オプション

| オプション | 意味 |
|---|---|
| `--complete` | 網羅的な探索 |
| `--limit N` | 状態の数の上限（既定 300 万） |
| `--json` | 結果を JSON で出す |
| `--trace` | 詰みの場面までの再現手順（エンジンの操作の列）も出す（`--json` では常に `path` に入る） |
| `--confirm-traps` | 詰みを見つけたら、その場面から TS 版と同じ見分け方で探索し直して確かめる |
| `--ts-exact` | TS 版と同じ状態の見分け方にする（状態の数まで TS 版と一致する。比べる用） |
| `--whole` | 編ごとに分けずに調べる |
| `--no-liveness` | 生きている変数だけを区別する工夫をやめる（確かめ用） |

確かめ用のサブコマンド:
- `replay <IR.json>`: 標準入力の操作を 1 歩ずつ実行し、各歩の状態を出す。
- `paths <IR.json> [個数]`: 見つけた状態までの操作の列を出す。
- `why <IR> <フラグ> <シーン>`: そのシーンでそのフラグを読む理由を調べる。

## TS 版との一致

エンジンの意味は TS（`packages/core`）に一本化している。Rust 版は、コンパイル済みの形（IR）を読み、分岐と状態に関わる命令だけを実行する。TS 版とずれていないことは、次で確かめる。

- `scripts/compare.ts`: `--ts-exact` の報告と状態の数が、TS 版と一致するか。
- `scripts/playdiff.ts`: 無作為に遊んで、各歩のシーン・フラグ・証拠品などが一致するか。
- `scripts/pathdiff.ts`: Rust 版が見つけた状態までの操作の列を、TS のエンジンで再生して一致するか。
- `packages/script/src/rust-verify.test.ts`（vitest）と `cargo test -p aa-verify`。

TS 版の verify（`verify*.ts`）やエンジンの意味を変えたときは、Rust 側にも手で移し、上の確かめを通すこと。
対応: 操作と step は `verify-actions.ts` ↔ `actions.rs`、詳しく調べる操作は `verify-inspect.ts` ↔ `inspect.rs`、
文章送りの途中で調べるのを試すかは `verify-inspect-sim.ts` ↔ `defer.rs`。
人物ファイルは、Rust 版では証拠品の後ろに並べた項目（`Evidence.profile`）として持ち、giveProfile・takeProfile は Give・Take にする
（profile の無い人物の出し入れは、つきつけに効かないので何もしない）。

## ビルド

```
cargo build --release -p aa-verify     # target/release/aa-verify
```

ライブラリは `wasm32-unknown-unknown` でもビルドできる。入口は `verify_json(ir, complete, limit)`。逆裁エディタへの組み込みはまだ（エディタは TS 版を Worker で動かしている）。
